## Nirogi AI — Emergency, Sharing, Family & Hindi Upgrade

One complete build implementing all six features from the document, on top of the existing 9-tool platform. UI/UX stays consistent with the current glass/health design.

### 1. Report actions — download, copy & WhatsApp share
A shared `ReportActions` component shown under every result (all 9 tools in `ToolRunner`, the prescription reader, and saved items on the History page).

- **Copy** — formats the report (title, risk/urgency, summary, sections, warnings, recommendations, specialist) into clean plain text and copies to clipboard.
- **Download** — generates a branded PDF ("Generated by Nirogi AI — nirogi-healthai.lovable.app" + disclaimer footer) using a client-side PDF library.
- **WhatsApp** — opens WhatsApp via `wa.me/?text=` pre-filled with the formatted report (tool name + date, key findings, urgency, what to do next, branding, disclaimer), matching the document's message layout. (WhatsApp links can carry text, not file attachments, so the PDF is a separate download — noted in the UI.)

A single `formatReport()` helper produces both the text and PDF content so they stay identical.

### 2. Emergency SOS
- A permanent red **SOS button**: a header button (desktop) and a fixed bottom-right floating button (mobile) with a subtle pulse animation, visible on every page via `SiteLayout`.
- New route **`/sos`** (public) with:
  - All India emergency numbers as one-tap `tel:` call buttons — 108 (ambulance), 112 (national), 100 (police), 181 (women), 1800-116-117 (poison), 080-46110007 (NIMHANS) — each with "when to use".
  - **Nearest hospitals**: uses browser geolocation to open a "hospitals near me" map search and shows the user's coordinates for sharing; a "Share my location" button builds an SMS/WhatsApp message with a map link.
  - **Your medical info for paramedics**: pulls the signed-in user's saved conditions, allergies, blood group and medicines from their profile so first responders can see them instantly.
  - Clear note that Nirogi connects to public services and is not its own emergency responder.

### 3. Health Score
- New `getHealthScore` server function computes a 0–100 score from existing data using the document's weights: BMI 15%, food/sugar from CalorieEye+SugarSense, medicine compliance 15%, tool-usage frequency 10%, CancerSense 10%, HeartSense 10%, ScanIQ 5%.
- Dashboard shows a large circular score with colour band (Excellent→Critical), week-over-week change arrow, top 3 factors lowering and top 3 raising the score, a weekly history line graph, and a motivational message.
- Weekly snapshots stored in a new `health_score_history` table to drive the graph.

### 4. Medicine Reminders
- New section in the dashboard: add/edit/delete reminders (medicine, dose, timings, with/without food, duration, special instructions, doctor, tablet count for refill).
- Stored in a new `medicine_reminders` table; doses tracked in `medicine_logs` (taken / missed) for the compliance that feeds Health Score.
- **In-app + browser notifications**: a client scheduler requests Notification permission and fires due-dose notifications while the site is open, plus a "due now / mark as taken" panel and a missed-dose follow-up. Weekly compliance summary shown.
- **Refill reminder** when ~5 days of tablets remain. New medicines are cross-checked against existing reminders via the MedGuard prompt, surfacing CRITICAL interaction warnings.

### 5. Family Profiles
- New `family_members` table (owner-scoped) supporting up to 6 members, each with the full profile fields + emergency contact.
- A **family member switcher** at the top of the dashboard; selecting a member runs all tools, history, health score and reminders for that person (member context passed through to tool runs and saved rows).
- **Family Health Overview**: one screen listing each member's health score, last tool used and any red alerts, with alerts surfaced on the main dashboard.

### 6. Hindi support (EN / हिंदी)
- A lightweight i18n context with an EN/हिंदी toggle in the header, persisted in localStorage.
- A translation dictionary covers navigation, buttons, tool names/taglines, dashboard, SOS, reminders, and error toasts.
- Tool and prescription AI prompts gain a language instruction so **results and reports come back in Hindi** when हिंदी is selected.

### Technical notes
- **Migrations** (each with GRANTs + RLS scoped to `auth.uid()` / owner): `family_members`, `medicine_reminders`, `medicine_logs`, `health_score_history`; add `emergency_contact` + `preferred_language` to `profiles`, and a nullable `member_id` to `scan_history` and `food_diary` so runs/history can be per family member.
- **New server functions** (all under `requireSupabaseAuth`): `health-score.functions.ts` (`getHealthScore`), `reminders.functions.ts` (CRUD + log dose), `family.functions.ts` (CRUD + `getFamilyOverview`). `runTool`/`analyzePrescription`/`getMyHistory` extended to accept `memberId` and a `lang` flag.
- **New components**: `ReportActions`, `SosButton` (floating + header), `HealthScoreCard`, `MedicineReminders`, `FamilySwitcher`, `FamilyOverview`; new `/sos` route; i18n provider + `useT()` hook.
- **PDF**: add a client-only PDF lib (e.g. `jspdf`) imported inside the click handler to avoid SSR issues.
- `ToolResult` and rendering are unchanged in shape; report formatting reads the existing fields. No changes to auto-generated Supabase files.
- All new dashboard data uses TanStack Query; no protected calls from public loaders (the `/sos` page reads profile only client-side when signed in).
